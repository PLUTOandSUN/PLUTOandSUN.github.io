ERP 图像放进 Transformer，相比普通透视图，主要有四类问题：

**几何畸变、边界不连续的假象、位置编码失真、以及 patch/token 语义不均匀。** 过去几年的工作基本都围绕这四点在改。([arxiv.org](https://arxiv.org/abs/2207.13689?utm_source=chatgpt.com)) ([openaccess.thecvf.com](https://openaccess.thecvf.com/content/CVPR2022/papers/Zhang_Bending_Reality_Distortion-Aware_Transformers_for_Adapting_to_Panoramic_Semantic_Segmentation_CVPR_2022_paper.pdf?utm_source=chatgpt.com))

先说问题。

第一，**ERP 有强几何畸变**。球面被展开成平面后，越靠近顶部和底部拉伸越严重，所以普通 ViT 里“大小一样的方形 patch”在真实球面上代表的面积和形状并不一样。这样一来，普通图像里成立的局部统计规律在 ERP 上会被破坏，token 的几何含义也不一致。PanoFormer、EGFormer、Trans4PASS 这类工作都把这个当成核心问题。([ecva.net](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136610193.pdf?utm_source=chatgpt.com)) ([openaccess.thecvf.com](https://openaccess.thecvf.com/content/ICCV2023/papers/Yun_EGformer_Equirectangular_Geometry-biased_Transformer_for_360_Depth_Estimation_ICCV_2023_paper.pdf?utm_source=chatgpt.com)) ([openaccess.thecvf.com](https://openaccess.thecvf.com/content/CVPR2022/papers/Zhang_Bending_Reality_Distortion-Aware_Transformers_for_Adapting_to_Panoramic_Semantic_Segmentation_CVPR_2022_paper.pdf?utm_source=chatgpt.com))

第二，**ERP 左右边界在图像上看似断开，但在球面上其实是相邻的**。普通 Transformer 若按平面图像处理，会把最左列和最右列当成远距离 token，破坏全景图的周期性。PanoSwin 就是专门针对这个问题设计了 pano-style shift window，让窗口机制尊重 panorama 的首尾相连属性。([openaccess.thecvf.com](https://openaccess.thecvf.com/content/CVPR2023/html/Ling_PanoSwin_A_Pano-Style_Swin_Transformer_for_Panorama_Understanding_CVPR_2023_paper.html?utm_source=chatgpt.com))

第三，**普通位置编码不适合 ERP/球面图像**。标准 ViT 的绝对位置编码默认是平面坐标系，但全景图在水平方向有循环性、在垂直方向有纬度相关的几何变化，所以普通 PE 会把“几何上等价”的位置编码成不合理的差异。PanoViT 针对这个问题设计了 recurrent position embedding，强调全景图在水平轴上的循环平移性质，而不是死记绝对起点。

第四，**全景任务往往比普通分类更依赖全局结构，但又不能丢掉局部几何细节**。普通 ViT 虽然擅长全局建模，但对局部边界、线结构和多尺度信息不如 CNN 稳定，尤其在数据量不大的全景任务上更明显。PanoViT 明确指出，预训练 ViT 对 panoramic images 并不理想，因此引入 CNN multi-scale features 作为 panorama 和 Transformer 之间的桥梁。

对应这些问题，过往工作大概走了五条解决路线。

第一条是 **改 patch/token 化方式**。  
PanoFormer 不直接只用 ERP 上的普通方块 patch，而是结合 tangent/spherical-domain patch 来减少畸变影响。PanoViT 也改了 token 化：对原始 panorama 用方形 patch，但对 CNN 多尺度特征图不再切普通块，而是切成沿水平方向排列的竖条 patch，再做 embedding。这样更贴近全景图“水平展开”的结构。([ecva.net](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136610193.pdf?utm_source=chatgpt.com))

第二条是 **改位置编码**。  
PanoViT 的 recurrent position embedding 是一个典型例子，它通过随机起始位置来弱化 ERP 水平绝对位置，强调全景图的循环平移特性。更一般地，很多 spherical / panorama Transformer 都会把经纬度、球面相对位置或 geometry bias 写进 PE 或 attention bias 里。 ([arxiv.org](https://arxiv.org/abs/2306.03403?utm_source=chatgpt.com))

第三条是 **在注意力里显式加入几何偏置**。  
Trans4PASS 通过 deformable patch embedding 和 deformable MLP，在 ERP 图像域里做 distortion-aware 适配。EGFormer 则更进一步，直接提出 equirectangular geometry-biased attention，让 local attention 带上 ERP 几何偏置。SGAT4PASS 也是这条思路，把 3D spherical geometry knowledge 更明确地融入 Transformer。([openaccess.thecvf.com](https://openaccess.thecvf.com/content/CVPR2022/papers/Zhang_Bending_Reality_Distortion-Aware_Transformers_for_Adapting_to_Panoramic_Semantic_Segmentation_CVPR_2022_paper.pdf?utm_source=chatgpt.com)) ([openaccess.thecvf.com](https://openaccess.thecvf.com/content/ICCV2023/papers/Yun_EGformer_Equirectangular_Geometry-biased_Transformer_for_360_Depth_Estimation_ICCV_2023_paper.pdf?utm_source=chatgpt.com)) ([arxiv.org](https://arxiv.org/abs/2306.03403?utm_source=chatgpt.com))

第四条是 **保持或恢复球面邻接关系**。  
PanoSwin 针对 panorama 的左右首尾相连设计了 pano-style shift window。更早的 Spherical CNNs、DeepSphere，虽然不是 Transformer，但它们从球面卷积和球面图结构角度说明了：如果不尊重球面邻接关系，模型会天然吃亏。这条思想后来被很多全景 Transformer 继承。([openaccess.thecvf.com](https://openaccess.thecvf.com/content/CVPR2023/html/Ling_PanoSwin_A_Pano-Style_Swin_Transformer_for_Panorama_Understanding_CVPR_2023_paper.html?utm_source=chatgpt.com)) ([arxiv.org](https://arxiv.org/abs/1801.10130?utm_source=chatgpt.com)) ([openreview.net](https://openreview.net/forum?id=B1e3OlStPB&utm_source=chatgpt.com))

第五条是 **CNN + Transformer 混合建模**。  
PanoViT 是最典型的代表：CNN backbone 先提 multi-scale features 补足局部纹理、边界和多尺度先验，再让 Transformer 负责全局关系建模。这种思路很实用，因为它承认纯 ViT 在小数据、强畸变全景任务里不够稳。

你可以把这些工作总结成一句很适合汇报的话：

**ERP 图像进入 Transformer 后，核心困难不在“能不能做 attention”，而在“平面 token 是否还能代表真实球面几何”。因此过往方法主要从 patch 划分、位置编码、几何偏置、周期边界建模以及 CNN-Transformer 混合架构五个方面来修正普通 ViT 对 ERP 的不适配。**
