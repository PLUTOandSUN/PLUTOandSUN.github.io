**SphereViT 的 patch token**，指的是 SphereViT 在处理全景图时，对图像分块后得到的主干视觉特征。和普通 ViT 一样，图像会先被切成 patch，每个 patch 变成一个 token；不同的是，SphereViT 不只是看平面图像纹理，还会结合球面坐标和球面嵌入去建模全景图的几何位置关系。所以这类 token 主要承载的是“这个局部区域看到了什么”的信息，比如物体外观、边缘、纹理、局部语义，以及它在全景球面上的位置关系。你可以把它理解成**全景版的视觉语义 token**，是主干输入，最像传统 VLM 里的视觉 token。

**几何 token**，是从 DA² 的几何输出里进一步编码出来的 token。DA²不是只提图像语义，它还显式预测了 distance 和 normal，并且可以进一步恢复 3D 点云，所以它的特征天然带有空间结构。这里的几何 token 不是直接把整张深度图塞进去，而是把这些几何信息做摘要、编码后得到一组 token，例如“某块区域离相机多远”“表面朝向哪里”“前方是不是可通行”“物体边界是不是凸出来”“这个区域和机械臂之间的空间关系是什么”。所以几何 token 主要回答的是**这个区域在三维空间中长什么样、在哪里、朝向如何**，它补的是 VLM 通常比较弱的 3D 结构信息。

**注意力派生 token**，则不是直接拿 attention map 当输入，而是把注意力矩阵进一步汇聚、压缩后形成更高层的关系摘要。因为原始 attention map 很大、很稀疏，而且不稳定，直接拿来做下游输入通常效果不好。但你可以从它里面提炼出一些很有价值的关系信号。比如：

- **显著区域摘要**：哪些区域被整体高频关注，可能就是任务关键区域；
- **长程依赖摘要**：图像中相距很远的两个区域是否强相关，比如“前方桌子”和“身后门口”；
- **跨极区关系摘要**：全景图里普通平面模型不容易处理的跨边界、跨极点关联，比如左右拼接边界两侧其实是连续空间。  
    所以这类 token 承载的不是“区域内容本身”，而是**区域和区域之间怎么关联、哪里值得重点看、全景长距离关系如何组织**。

你可以把三者的区别记成：

- **patch token**：看到了什么，偏语义外观
- **几何 token**：它在三维里是什么样，偏空间结构
- **注意力派生 token**：哪些区域彼此相关，偏关系建模

如果把它们放到一个 VLA 里，最理想的分工就是：patch token 负责“识别目标”，几何 token 负责“理解可操作空间”，注意力派生 token 负责“告诉模型应该重点关注哪里以及远距离区域如何联动”。这样你接到 VLM / VLA 后，模型就不是只会看图说话，而是更有希望做出面向全景场景的动作决策。
